1. Project Overview

The Military Asset Management System (MAMS) is an enterprise defense logistics platform architected to maintain 100% accountability of critical military assets—including combat vehicles, weapons, artillery, and ammunition—across distributed military installations, forward depots, and strategic commands.

Core Objectives

  • Live Inventory Reconciliation: Automatically maintain accurate Opening, Net Movement, and Closing Balances across all installations.
  • Inter-Base Movement Governance: Ensure secure multi-base transfers with sender stock deductions and receiver inventory credits.
  • Troop Allocations & Returns: Real-time tracking of weapon assignments to field personnel and operational ammunition expenditures during drills.
  • Tamper-Proof Audit History: Append-only chronological movement ledger recording all officer actions, timestamps, and reference identifiers.

Assumptions

  • Every movement transaction operates under ACID transactional boundaries; partial commits are strictly prohibited.
  • All military personnel and base installations possess unique identification codes (e.g., Service Numbers, Base Codes).
  • Asset types are categorized into Durable Assets (reusable equipment like rifles and tanks) and Consumable Ordnance (ammunition and flares).

Limitations & Future Enhancements

  • GPS real-time satellite transit tracking between bases can be integrated in Phase II.
  • Barcode / RFID automated scanner integration for armory checkout counters.

3. Data Models & Relational Schema

MAMS utilizes a normalized relational schema with strict Foreign Key constraints to prevent orphan movement records and maintain mathematical balance consistency:

Table / Entity Primary Fields & Data Types Relationships & Purpose
bases id (BIGINT PK), name (VARCHAR), code (VARCHAR UK), location, commander_name, status Represents military installations. One base has many users, inventories, and movements.
users id (BIGINT PK), username (UK), email (UK), password (BCrypt), role (ENUM), base_id (FK) Stores officer credentials and operational roles. Linked to assigned base installation.
equipment_types id (BIGINT PK), name (UK), code (UK), category (ENUM), unit_of_measure, is_expendable (BOOL) Master catalog defining defense asset specifications (Weapons, Vehicles, Ammunition, Radios).
inventories id (BIGINT PK), base_id (FK), equipment_type_id (FK), opening_balance, available_qty, assigned_qty, expended_qty, closing_balance Maintains live stock balances per base and equipment. Unique composite constraint on (base_id, equipment_type_id).
movement_ledger id (BIGINT PK), base_id (FK), equipment_type_id (FK), movement_type (ENUM), quantity, reference_type, created_by, timestamp Append-only immutable audit ledger recording purchases, transfers, assignments, returns, and expenditures.

4. Role-Based Access Control (RBAC)

MAMS enforces three-tier defense clearance levels implemented using Spring Security filters, JWT claims, and React route guards:

Operational Role Permissions & Functional Scope Enforcement Mechanism
HQ Supreme Admin
ROLE_ADMIN		 Global visibility across all military installations. Full authority to create users, register bases, modify asset catalog, approve purchases/transfers, and access complete system logs. @PreAuthorize("hasRole('ADMIN')")
Frontend: Full navigation access.
Logistics Officer
ROLE_LOGISTICS_OFFICER		 Authorized to record asset procurements, execute inter-base supply transfers, register catalog items, and view logistical stock movements across sector depots. @PreAuthorize("hasAnyRole('ADMIN','LOGISTICS_OFFICER')")
Personnel & troop assignments are strictly restricted.
Base Commander
ROLE_BASE_COMMANDER		 Command over assigned tactical base. Authorized to issue weapons to soldiers, record shift returns, log ammunition expenditures, and transfer assets to sister bases. @PreAuthorize("hasAnyRole('ADMIN','BASE_COMMANDER')")
Access restricted to the commander's base data.

5. API Logging & Transaction Auditing

  • Append-Only Movement Ledger: Every purchase, transfer, weapon issuance, shift return, and ammunition expenditure writes an immutable record to movement_ledger with authenticated officer identity and server timestamp.
  • Spring Security Audit Filters: Inbound REST requests capture user credentials, HTTP method, URI path, and client IP in application logs.
  • Security Alert Dispatcher: HTTP 403 Forbidden attempts trigger real-time client-side security event notifications without logging out the active officer.

6. Setup Instructions (Local & Cloud)

1. Backend Setup (Spring Boot)

cd backend
# 1. Compile and package
mvn clean compile

# 2. Run backend server (starts on port 8080)
mvn spring-boot:run
  • Backend Base URL: http://localhost:8080/api
  • Health Check: http://localhost:8080/api/health
  • Swagger UI API Docs: http://localhost:8080/swagger-ui/index.html

2. Frontend Setup (React / Vite)

cd frontend
# 1. Install dependencies
npm install

# 2. Launch Vite development server
npm run dev -- --port 5173
  • Web Client: http://localhost:5173
  • Public Architecture & Specs: http://localhost:5173/public-docs
